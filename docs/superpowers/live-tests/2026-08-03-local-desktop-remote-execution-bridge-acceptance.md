## Sixteen acceptance criteria

1. A fresh read-only provider check proves the pre-test inventory is exactly zero before any paid mutation, and its sanitized timestamp is recorded.
2. The displayed offer identity, hourly rate, hard price cap, disk, finite or explicitly no-limit duration, maximum charge, and durable intent exactly match the single created instance.
3. No instance exists before the user confirms the sole paid `Louer et préparer` action, and the durable intent exists before that provider call.
4. The official independent `ComfyUI Vast` environment opens beside the local environment inside ComfyUI Desktop and never in an external browser; its displayed origin is the stable `127.0.0.1` loopback relay rather than a public pod URL.
5. The current canvas, saved workflows, palette, background image, approved UI extensions, and Agent Panel are visible; Agent Panel remains on the Mac, can safely modify the active Vast canvas, and can prepare an ordered batch.
6. Every expected custom-node class and exact model digest is present on the pod, model selectors list the expected models, and readiness identifies every immutable Hugging Face, Civitai, local-upload, or optional R2 source used.
7. Local prompt submission and local GPU execution remains unused throughout the Vast-role campaign, while ordinary Run in the independent local environment remains local before and after it.
8. A native Run and an Agent Panel batch execute the current `ComfyUI Vast` canvas on the pod GPU with distinct durable jobs and no second paid confirmation.
9. Active nodes, sampler progress, progress state/text, previews, `executed`, native execution errors, and `execution_success` behave in the normal Desktop interface and reconcile to the durable Cloud Vast panel.
10. A persistent `SaveImage` result is size/digest verified under `output/cloud-vast/<session>/<job>` on the Mac, while a legitimate temporary `PreviewImage` descriptor remains available as a preview and is excluded from final harvesting.
11. Closing and reopening the `ComfyUI Vast` Desktop environment catches up from its durable cursor without a duplicate prompt submission, duplicate event, or duplicate output.
12. One close/reopen and local-backend restart/reconnect sequence reconstructs the session and active or completed job from the same SQLite record plus one atomic worker snapshot, without resubmission.
13. A second compatible job reuses the healthy instance, transfers only a real dependency delta, preserves installed identities, and completes independently of the first job.
14. The secret-free journal contains useful typed phase, correlation ID, event/output cursor, last safe probe, bounded sanitized worker-log evidence, retry state, output identity, and timestamps without any credential or signed URL.
15. Measured readiness is labeled cold, pre-positioned, or warm; transfer, installation, bootstrap, health, profile, Agent bridge, and total readiness durations remain separate rather than becoming one unsupported ten-minute claim.
16. One explicit destroy removes the authorized instance; a fresh read-only check proves the final inventory is exactly zero, and the final durable local state reports `billing_may_continue=false` with teardown timestamps.

sanitized evidence. The paid pod must not be hot-patched or replaced, a second
instance must not be created, scope must not be expanded, and a failed action
must not be repeated without another explicit human decision that names the
new exact action and bounds. Closing either Desktop environment is not teardown;
only the authorized deadline path or explicit destroy plus fresh inventory
absence is accepted as billing proof.

The campaign is accepted only when every criterion has evidence tied to the
same immutable campaign identity and the final inventory/billing proof is
